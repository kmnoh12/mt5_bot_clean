### Phase C — Implement robust profitability architecture, not blind tuning
Implement small but meaningful changes that improve robustness and prevent negative expectancy. Prefer testable components.

Required improvements if not already present:
1. A validation/backtest metrics layer that computes at least:
   - trades, win rate, avg win, avg loss, expectancy, profit factor, max drawdown, fees/cost estimate, exposure/churn counts.
2. A quality-first entry/risk profile that lowers destructive defaults:
   - default risk-per-trade sane cap
   - stricter max daily entries/global entries
   - spread/cost-edge guard default conservative
   - cooldowns/min-hold against churn
   - symbol-specific risk/entry caps
3. Regime/strategy coordination:
   - avoid simultaneous conflicting strategy behavior
   - prefer one primary strategy per symbol/regime or add arbitration/scoring
   - make low-quality/no-trade days valid outcomes
4. Exit architecture improvements:
   - avoid tiny quick exits and repeated close spam
   - preserve winners with trailing/profit-lock only when expected cost/edge supports it
   - don't force TP if trend breakout has better expectancy unless backtest supports it
5. Backtest/OOS hygiene:
   - add walk-forward or train/test split scaffolding if missing
   - make `backtest` usable without MT5
   - tests for metrics and conservative profile behavior

Do not overfit to imaginary data. If no data is available, implement the metrics/validation scaffold and safer defaults, with tests demonstrating behavior.
